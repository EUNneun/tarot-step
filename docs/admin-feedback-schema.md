# TarotStep 관리자 피드백 데이터 구조

관리자 기능 안정화를 위해 사용자 진행 데이터(`users/{uid}`)와 관리자 피드백 관리 데이터를 분리한다.

## 현재 단계

- 현재 관리자 화면은 기존 `users` 컬렉션을 읽는다.
- 이 문서는 다음 단계의 데이터 구조만 정의한다.
- 아직 실제 앱의 읽기/쓰기를 이 컬렉션으로 전환하지 않는다.

## 권장 컬렉션

`adminFeedback/{questionId}`

```json
{
  "questionId": "Q001",
  "status": "open",
  "adminComment": "정답 근거 설명 보강 필요",
  "requestedAt": "2026-09-14T00:00:00.000Z",
  "improvedAt": null,
  "updatedAt": "2026-09-14T00:00:00.000Z"
}
```

### status

- `open`: 개선 필요
- `done`: 개선 완료
- `reopened`: 개선 완료 후 재검토 필요

## 피드백 이벤트

필요 시 원본 사용자 이벤트는 별도 컬렉션으로 분리한다.

`feedbackEvents/{eventId}`

```json
{
  "questionId": "Q001",
  "type": "needs-more",
  "userId": "uid",
  "createdAt": "2026-09-14T00:00:00.000Z"
}
```

## 전환 원칙

1. 기존 관리자 화면이 안정적으로 동작하는지 먼저 확인한다.
2. 새 컬렉션 쓰기를 먼저 추가하되 기존 `users` 데이터 기록은 유지한다.
3. 데이터가 정상 누적되는 것을 확인한 뒤 관리자 조회를 새 컬렉션으로 전환한다.
4. 전환 완료 후에만 기존 전체 `users` 스캔 의존성을 제거한다.

이 순서를 지켜 관리자 기능 변경이 사용자 학습 데이터에 영향을 주지 않도록 한다.
